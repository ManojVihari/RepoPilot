How it works

Three steps, no changes to your application.

  1. 1

    Scan

    The scanner parses your code with tree-sitter in CI or locally. It doesn't need a build, a running app or annotations. It finds endpoints, request and response models, validation, security and every database, cache, queue and HTTP call.

  2. 2

    Document

    The server turns the scan into documentation with your local Ollama model, versions it by contract, and links it to the architecture. Without a model it still builds docs from the scanned facts.

  3. 3

    Review

    Browse the dashboard, compare versions, check the impact of a change and hand QA a plan, all before the change is merged.

Private by default

Your code is analysed on your own machines and documentation is written by a local model. Nothing is sent to a third-party service.

Try it on a repository

Document a whole local repository

python scripts/document_local_repo.py ~/code/my-service

Start the server and open the dashboard

cd server && python run.py

Or scan every commit in CI

docai-scan --repo . --commit "$GIT_COMMIT" --server https://repopilot.internal
